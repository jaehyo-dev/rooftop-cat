# v0.7.0 "강화 상점 + 미션" 설계 (1단계, 2026-11-11)

기준: GAME_SPEC.md "2026-11-11 강화 상점·미션 결정", QUALITY_BAR.md, ART_BIBLE.md, review/v0.6.0/PLAN.md 16·18·21번.
이 단계는 설계와 시안만 한다. 코드는 측정용 한 곳(`tests/balance_bot.gd`가 생선 수·거리·최고 콤보·퍼펙트·질주 생선을 돌려줌)과 측정 스크립트(`review/v0.7.0/economy.gd`)만 바꿨다.

## 1. 화면 흐름

```
켜기 ─▶ 시작 화면 ─[시작]──────────────▶ 판 ─▶ 결과 카드 ─[다시 하기 / 빈 곳 터치]─▶ 판
          │  (부스터 3칸 켜고 끄기)                    │ (부스터 3칸 켜고 끄기)
          ├─[상점]─▶ 상점 (강화 | 부스터 탭) ◀──────────┤─[상점]
          └─[미션]─▶ 미션 (일일 3 · 주간 3 · 등급) ◀────┘─[미션]
          상점·미션의 [뒤로] = 온 곳(시작 화면 또는 결과 카드)으로
```

- **시작 화면은 새 씬이 아니라 게임 화면 위의 겹침(오버레이)**: 뒤에는 지금 World가 첫 옥상에서 멈춘 채(고양이 앉아 꼬리 흔듦) 그려지고, 앞에 종이 카드 메뉴. [시작]을 누르면 카드가 옆으로 빠지며 그 자리에서 바로 달린다. 씬을 새로 불러오지 않아 기다림이 없다.
- **첫 실행도 한 번에 시작**: [시작] 버튼이 화면에서 가장 크고, 버튼이 아닌 빈 곳을 눌러도·스페이스를 눌러도 시작한다. 처음엔 부스터가 0개라 부스터 칸은 흐리게 보이고 고를 게 없다. 첫 판 결과 카드에서 "상점에서 강화를 살 수 있어요" 한 줄 안내(첫 강화 300마리가 첫 판 수입으로 대개 살 수 있음, 3번 표).
- **부스터 고르기 = 시작 버튼 옆 작은 칸 3개**(따로 화면을 두지 않음). 칸마다 아이콘 + 가진 개수. 누르면 켜짐/꺼짐, 여러 개 같이 켤 수 있다. 0개인 칸을 누르면 상점 부스터 탭으로 간다. 켠 부스터는 판이 시작되는 순간 1개씩 줄어든다(시작 전에 상점·미션으로 가도 안 줄어듦).
- **결과 카드**: 지금 카드(점수·거리·생선·최고 콤보·최고 점수·모은 생선)에 아래 줄을 더한다: [다시 하기](크게) · [상점] · [미션] + 부스터 칸 3개. 이번 판에 깬 미션이 있으면 카드 위에 쪽지가 하나씩 붙는다(보상 생선은 그때 들어옴). 지금처럼 0.8초 뒤 빈 곳 터치 = 다시 하기는 그대로(버튼 자리는 점프·재시작으로 받지 않음, v0.6.0 2b의 "버튼 자리 터치가 점프가 됨" 버그를 같은 방식으로 막음).
- **다시 하기의 부스터**: 결과 카드의 부스터 칸은 늘 꺼진 채로 뜬다(실수로 계속 쓰지 않게). 켜고 다시 하기를 누르면 적용.
- 판 중에는 상점·미션에 갈 수 없다(일시정지 화면은 이번 범위 밖).
- 화면 크기: PC 1280x720, 휴대폰 가로 844x390(게임 화면 1558x720). 버튼은 화면 높이 12% 이상(휴대폰에서 약 47px 이상).

## 2. 저장

지금: `user://save.cfg`(ConfigFile), `[save] version=1`, `[record] best_distance, best_score`, `[wallet] fish`. 게임 끝에만 저장.

### 2-1. 새 칸 (덧붙이기만, architect 지적 1 반영)
같은 주소의 이전 버전(versions/v0.6.0 등)이 같은 `save.cfg`를 계속 쓴다. v0.6.0의 `_save_int`(`best_record.gd:56-62`)는 쓸 때마다 `version=1`로 되돌리고 `best_score`에 10점 기준 점수를 쓴다. 그래서 **version 숫자로 아무것도 판단하지 않고, v0.7.0은 예전 키를 건드리지 않고 새 키만 덧붙인다.**

| 칸 | 키 | 값 |
|---|---|---|
| save | version | 2 (기록용, 판단에 쓰지 않음. 이전 버전이 1로 되돌려도 상관없음) |
| record | best_distance | 그대로 같이 씀(거리 계산은 안 바뀜) |
| record | best_score | **v0.7.0은 읽지도 쓰지도 않음**(v0.6.0 이전 버전 전용) |
| record | best_score2 | v0.7.0 최고 점수(생선 5점 기준). 없으면 0 = "새로 시작" |
| wallet | fish | 모은 생선(같이 씀: 이전 버전에서 번 생선도 들어옴) |
| upgrades | dash, yarn, combo, gold, cookie, fish | 0~10 |
| boosters | dash_start, bell_start, fish_bonus | 가진 개수(0~99) |
| missions | day / week | 일일을 뽑은 날 "2026-11-11", 주간을 뽑은 주의 월요일 |
| missions | daily / weekly | [{id, target, progress, done}] x3 (보상은 깨는 순간 자동) |
| missions | prev_daily / prev_weekly | 어제·지난주 id 목록(뽑기에서 뺌) |
| missions | swaps_today | 오늘 바꾼 횟수 (날이 바뀌면 0) |
| missions | week_daily_done, week_full_days | 이번 주 깬 일일 수, 일일 3개를 다 깬 날 수 (`w_daily_*`, `w_alldays`) |
| rank | level, xp | 고냥이 등급과 지금 등급 안 경험치 |
| stats | runs, fish_total | 누적 판 수, 지금까지 번 생선(배수 전 `sim.fish` 합, 가격 다시 맞추기용) |

- 옮기기 단계가 없다: 없는 키는 0으로 읽고, 첫 v0.7.0 결과 카드에서 `best_score2`가 없었으면 "점수 계산이 바뀌어 최고 점수를 새로 시작해요" 한 번. 모은 생선은 같은 키라 그대로.
- 값은 int·String·Array·Dictionary만 쓴다.

### 2-2. 저장 시점과 안전 (architect 지적 2 반영)
- 게임 끝(생선·기록·미션 진행), 사기, 미션 바꾸기, 판 시작(부스터 소모) 때 저장.
- **깨진 파일을 0으로 덮어쓰지 않는다**: 파일이 있는데 `load`가 실패하면 원본을 `save.cfg.broken`으로 복사해 두고, `save.cfg.tmp`가 있으면 그것을 읽는다. 둘 다 안 되면 0에서 시작(원본은 .broken에 남음). 지금 `_save_int`처럼 load 실패를 무시하고 덮어쓰지 않는다.
- 쓰기는 `save.cfg.tmp`에 쓰고 이름을 바꿔 덮는다(쓰다가 꺼지면 이전 파일이 남게). 웹(IndexedDB)에서 rename이 반영되는지 2a에서 한 번 확인하고, 안 되면 바로 쓰기.
- 판 중간에 창을 닫으면 그 판 생선은 사라지는 지금 shortcut은 유지. 판 시작 때 부스터는 이미 줄어 있어 "닫으면 부스터만 잃음"을 감수(되돌리기 꼼수 방지).
- shortcut: 이전 버전 탭과 v0.7.0 탭을 동시에 열면 나중에 저장한 쪽이 덮는다. 한 사람용이라 감수하고 코드에 주석으로 남긴다.

### 3-2. 질주 6초가 기존 규칙과 맞는지 (코드 확인)
- **착지 옥상**: `_landing_roof()`(`runner_sim.gd:955`)는 "남은 질주 거리 < 생성 범위 2200 + 300"일 때 요청한다. 전체 길이가 아니라 남은 거리 기준이라 6초여도 같은 때 같은 길이(다음 단계 속도 x 1.5초)로 생긴다. → 바꿀 것 없음.
- **단계 넘김**: 단계 사이는 가장 짧아도 14초라 6초 질주가 두 단계를 넘지 않는다. 착지 길이는 이미 `arrival_speed`(다음 단계 속도)로 잼. → 맞음.
- **질주용 생선 줄**(`_lay_dash_line`, `:647`): `x + dash_time * v`까지와 착지 옥상 왼쪽까지 깐다. 길어지면 그만큼 더 깔 뿐 "어느 x든 한 줄" 규칙(`FishRoad.add_one_line`)은 그대로. 부술 것도 `dash_time` 기준이라 더 놓인다(질주당 부순 수 증가 = 행동 미션에 유리).
- **사람 기준 검사**(`human_check.gd`): 구간·생선 길을 질주 없이 검사하므로 질주 길이와 무관. 다만 **`test_fish_line.gd`(질주를 주기적으로 넣은 120초 판 겹친 쌍 0개)와 `test_power_items.gd`("4초는 달림")는 10단계 perks로도 돌린다**(2a에서 추가).
- **첫 질주 20~25초 규칙**(`test_balance.gd`): "질주로 출발" 부스터를 켜면 그 앞에 질주가 하나 더 생긴다. 테스트는 부스터 없는 판 기준 그대로 두고, 부스터 판은 따로 "출발 질주 → 착지 → E2 질주가 겹치지 않음"과 "출발 1초 뒤 질주를 시작할 때 아직 짧은 앞 옥상에서도 `_replace_with_dash_line`(`:634`)이 줄을 충분히 까는지"를 확인.
- **봇 결과**(4번): 10단계 값으로 바꿔 돌린 판에서 질주 뒤 3초 안 떨어짐이 늘지 않는지 2a에서 `balance_report.gd`로 다시 본다.

### 3-3. 강화 하나씩 10단계로 바꿔 본 봇 결과 (콤보 유지·쿠키 간격·질주)
`balance.gd` 값을 잠시 바꿔 `economy.gd`를 돌리고 되돌림(시드 30, 실력별, 최대 900초). 결과 원본: `economy_result_{cookie,dash,combo,max}.md`.

| 바꾼 것 | 초보 판 길이 평균 / 가운데 | 익숙함 평균 / 가운데 / 하위25% | 숙련 평균 | 익숙함 생선 평균 |
|---|---|---|---|---|
| 없음 (v0.6.0) | 87 / 71초 | 240 / 164 / 103초 | 595초 | 2,750 |
| 쿠키 90→70초 | 91 / 71 | 249 / 234 / 104 | 595 | 2,855 (+4%) |
| 질주 4→6초 | 90 / 80 | 266 / 242 / 137 | 610 | 3,067 (+12%) |
| 콤보 유지 3→5초 | 87 / 71 | 240 / 164 / 103 | 595 | 2,750 (0%) |
| 6개 전부 10단계 | 93 / 80 | 273 / 244 / 206 | 612 | 3,192 (+16%) |

- **콤보 유지 시간은 효과가 0이다.** 점수·최고 콤보가 시드마다 한 자리도 안 바뀜. 생선 길이 촘촘해(초당 6~13개) 3초 동안 못 먹는 일이 거의 없고, 콤보는 부딪힘과 "필수 생선 놓침"으로만 끊긴다(v0.6.0 PLAN 16번 규칙). 이대로면 돈을 내도 아무것도 안 바뀌는 강화가 된다. → **12번 "사용자가 정할 것" 1번**: 같은 이름("못 먹어도 안 끊기는 시간")을 살려 **놓친 뒤 봐주는 시간 0 → 2초**(놓쳐도 그 시간 안에 다음 생선을 먹으면 안 끊김, 0단계 = 지금과 같음)로 바꾸기를 제안. 2a에서 봇으로 점수 변화를 재고 단계 값을 맞춘다. 배수는 콤보 80개(20 x 4)에서 x5로 막혀 이 강화의 실제 가치는 "끊긴 뒤 x5로 다시 오르는 8~13초"뿐이고, 0.2초만으로도 "하나 놓침" 대부분을 구할 수 있어 값은 0~1.0초로 좁게 잡을 가능성이 크다(architect). 생선 수(경제)에는 영향 없음.
- **하트 쿠키 70초는 "작은 버티기"가 맞다**: 판 길이 평균 +4%(초보·익숙함), 숙련 0%. 다만 익숙함 가운데값이 164 → 234초로 크게 뛴다(90~160초에 끝나던 판 무리가 첫 쿠키 70초 덕에 살아남음). 평균이 작게 움직여서 유지. 10단계에서도 150초 뒤 6배 간격 규칙은 그대로라 오래 버티는 사람에게는 효과가 없다.
- **버티기는 질주 6초가 더 크다**(익숙함 평균 +11%, 하위25% 103 → 137초): 질주 중 무적 + 위험한 구간을 건너뛰는 거리 +50%. "점수·생선 위주" 강화지만 버티기도 같이 오른다. 6개 전부 합해 판 길이 평균 +7%(초보)·+14%(익숙함)·+3%(숙련). 난이도가 무너질 정도는 아니라고 판단해 유지하고, 2a에서 "질주 뒤 3초 안 떨어짐"과 함께 다시 본다.
- **점수**: 생선 점수 5→25가 가장 크다. 10단계 전부일 때 익숙함 판 점수 가운데값이 0단계(생선 5점) 약 30,000 → 217,000(약 7배). 최고 점수는 강화를 살수록 크게 오르는 기록이 된다(의도대로 "점수 위주").

|---|---|---|---|---|

| 숙련 | 3일 | 6일 | 8일 | 8% |

- 초안 가격이면 보통 플레이어가 **1주**에 다 산다(목표 2주의 절반). 제안 가격이면 **13~18일**(봇 그대로 ~ 사람이 봇의 70%), 미션 비율 18%(목표 약 20%).

### 4-3. 부스터 가격
| 부스터 | 초안 | 제안 | 판단 |
|---|---|---|---|
| 질주로 출발 | 500 | 500 | 앞 구간을 건너뛰고 질주 생선 약 60~150마리. 버티기용이라 손해·이득보다 "편한 출발" |
| 방울 달고 시작 | 400 | 400 | 하트 하나 값. 그대로 |
| 생선 +50% | 500 | **800** | 아래 표 |

생선 +50%가 값보다 이득인 판 (이득 = 그 판 생선 x 0.5 > 값):
| 실력 | 500일 때 (판 생선 1,000 이상) | 800일 때 (1,600 이상) | 한 판 평균 이득(값 뺌), 800일 때 |
|---|---|---|---|
| 초보 | 약 20% | 약 5% | -400 |
| 익숙함 | 약 73% | 약 52% | +575 |
| 숙련 | 거의 100% | 거의 100% | +2,917 |
- 500이면 익숙함부터 거의 늘 이득이라 "안 쓰면 손해"인 세금이 된다. 800이면 익숙함에게 반반 내기, 숙련에게는 꾸준한 이득. 초보에게는 손해라 상점 설명에 "멀리 갈 자신 있을 때"를 적는다.
- 부스터는 미션·등급 보상으로도 준다(6번) → 초보도 공짜로 써 볼 수 있다.
- 생선 +50%는 **지갑에만** 더한다(`ceil(sim.fish x 0.5)` 추가). 미션 진행(`d_fish_*`, `w_fish_*`)과 `stats.fish_total`은 배수 전 `sim.fish`로 세고, 미션·등급 보상에는 곱하지 않는다.

### 5-4. 뽑는 규칙
- 일일 3개 = **기록 1 + 누적 1 + 행동 1**, 난이도는 쉬움 1·보통 1·나머지 하나는 아무거나(어려움 포함).
- 같은 "주제"(거리·생선·콤보·단계·질주·장애물·트램펄린·점프·아이템)는 하루에 하나만. 예: d_dist_1과 d_dist_c는 같은 날 안 나옴.
- 어제 나온 id는 오늘 안 나옴(저장에 어제 목록을 남김). 주간은 지난주 id를 피함.
- 주간 3개는 서로 다른 주제, `w_daily_*` 또는 `w_alldays` 중 하나는 꼭 들어감(일일을 하게 만드는 축).
- 시드 = 날짜 키 해시. 같은 날 같은 미션(다시 켜도 같음).
- **바꾸기**: 깨지 않은 미션 하나를 같은 종류(기록/누적/행동)의 다른 후보로 바꾼다(오늘 나온 것·어제 것 제외). 값은 그날 몇 번째인지에 따라 **200 → 400 → 800**, 그 뒤 800(`swaps_today`는 날이 바뀌면 0). 주간 미션도 바꿀 수 있고 1,000 고정. **바꾸면 진행은 사라진다.** 바꿀 후보가 없으면 바꾸기 버튼을 숨긴다.
- 후보가 모자라면(종류·주제·어제·오늘을 다 빼서 0개) 제외 조건을 "어제 것 → 주제" 순서로 하나씩 푼다. 행동형이 9개뿐이라 빠듯하므로 테스트로 모든 날짜 시드 365개에서 3개가 뽑히는지 확인.
- 진행은 판이 끝날 때 한꺼번에 반영(예외: `w_upgrade`는 사는 순간 오름, `w_daily_*`·`w_alldays`는 일일을 깨는 순간 오름. 판 중에 깨지면 HUD 위에 작은 쪽지 "미션 완료" 1초만, 보상은 결과 카드에서). 기록형은 그 판 값, 누적·행동형은 더함.
- 보상은 자동으로 받는다(받기 버튼 없음, 결과 카드에 쪽지가 붙으며 생선 숫자가 오름). 미션 화면에서 깬 것은 발바닥 도장.

## 6. 고냥이 등급

경험치는 미션에서만(일일 10~20, 주간 50~70). 보통 플레이어 하루 약 45 + 주간 하루 평균 약 25 = **약 70/일**.

| 1 | 아기 고냥이 | 100 | 0 | 첫날 | - |
| 2 | 골목 고냥이 | 150 | 100 | 2일 | 생선 1,000 + 부스터 1개(질주로 출발) |

| 6 | 전봇대 고냥이 | 350 | 1,000 | 15일 | 생선 3,000 + 부스터 1개씩 |

- 2주 안 등급 보너스 합(2~5등급) = 생선 7,000 + 부스터 약 7개 → 하루 약 500. 4-2 계산의 "등급 보너스 하루 400"과 비슷(부스터는 그만큼 부스터 지출을 줄임).

- 시작 화면에 배지(얼굴 + 등급 색 테두리) + 경험치 막대, 미션 화면 아래에 큰 막대. 오를 때 결과 카드 위에 배지가 도장처럼 찍힘 + 축하 별(v0.6.0 결과 카드 별 재사용).
- 로직: `scripts/logic/cat_rank.gd`(새): 경험치 더하기 → 오른 등급 목록과 보너스. 표는 `balance.gd`.

## 7. 날짜
- 기기 시간(`Time.get_datetime_dict_from_system()`, 지역 시간) 기준. 한 사람용이라 시간 조작은 막지 않는다.
- **일일 키** = "YYYY-MM-DD". 시작 화면·결과 카드·미션 화면을 열 때와 판이 끝날 때 키를 비교해 다르면 일일 미션을 새로 뽑는다. **판 시작 때(부스터 소모 저장 시점)에도 날짜를 확인해 새로 뽑고, 그 판의 진행은 "판 시작 때 있던 미션"에 넣는다**(architect 지적 9: 23:59 결과 카드에서 00:01에 다시 하기를 눌러도 새 날 미션에 들어감). 판 도중 자정을 넘기면 판 끝에서 먼저 반영 → 그다음 날짜 확인, 받지 않은 보상은 새로 뽑기 전에 자동으로 받는다(깬 미션 보상이 사라지는 억울함 방지).
- **주간 키** = 그 날짜가 속한 주의 월요일 "YYYY-MM-DD"(요일에서 거꾸로 계산, 0시 기준). 일요일 23:59 → 월요일 0:00에 바뀜. 처리 순서는 일일과 같다.
- 깬 미션 보상은 깨는 순간 들어오므로 날이 바뀌어 사라지는 보상은 없다.
- 시간을 뒤로 돌려 키가 예전 날짜가 되면: 키가 "다르면" 새로 뽑으므로 다시 뽑힌다(같은 날 시드라 같은 미션이 다시 나옴, 진행은 0). 막지 않음.
- 뽑기 시드 = 날짜 키 문자열의 해시(+ 바꾼 횟수). 테스트는 날짜를 넣어 고정.
- 로직: `scripts/logic/day_clock.gd`(새): `day_key(datetime)`, `week_key(datetime)` 순수 함수. 테스트: 자정 직전·직후, 일요일→월요일, 월말·연말(12-31 → 01-01, 주가 해를 넘김), 윤년 2-29.

사용자 플레이 피드백 4가지(결과 버튼, 사고 받는 연출·소리, 도장 쿵, 지저분한 UI)와 디렉터 결정을 반영. 버전은 그대로(v0.7.0-shop 브랜치).

### 18-1. 만든 것
- **결과 카드**: 부스터 칸 → 큰 [다시 하기] + [메인 화면](받을 미션 빨간 숫자는 오른쪽 위). 상점·미션 아이콘 뺌. 카드가 떠 있는 동안 판 HUD(거리·BEST·생선·점수·콤보·하트) 숨김. BEST 쉼표. 첫 판 안내는 "메인 화면의 상점에서 강화를 살 수 있어요".
- **연출** (`UiKit.stamp·squash·shake·burst·float_text·fly·finish`, 화면마다 `MenuScreen.track/finish_fx`):
  - 강화: 버튼 찌그러짐 → 지갑 생선 3마리가 새 단계 점으로 → 점 톡 + 작은 별 → "지금" 값 튐. 소리 = 강화 소리를 단계마다 반음씩 높게(빠르기 2^((단계-1)/12)). 10단계는 팡파르 + 별 많이(점·그림 두 곳).
  - 부스터: 설명 그림이 목록의 개수 칸으로 쏙 → "+1" 떠오름 + 개수 튐 + 쏙 소리.
  - 미션 받기: 도장이 위에서 크게 휙 내려와 쿵(화면 흔들림 0.14초·6px, 잉크 방울 9개, 도장 납작했다 돌아옴) → 생선이 지갑으로. 미션 화면을 열 때 지난번보다 등급이 올랐으면 리본 배지도 쿵. 결과 카드 등급 배지도 휙 + 쿵 + 흔들림 + 잉크·별.
  - 기다리지 않게: 누를 때마다 앞 연출을 끝 모습으로 넘기고(값·지갑이 다 참) 바로 다음. 연출 중에도 누름을 받음.
- **소리 4종** (`tools/make_sfx.py`): 휙(whoosh)·쿵(thud)·팡파르(fanfare)·쏙(pop_in). 다른 메뉴 소리와 같은 -17dB, 미리 듣기 `2c-juice/sounds/juice_sounds_preview.wav`(생선 기준 → 휙+쿵 → 강화 1·5·9단계 → 팡파르 → 쏙).
- **깔끔한 UI** (`tools/make_ui_paper.py`가 직접 그림, Codex 안 씀): 판·쪽지·코르크·주황·크림 버튼을 9칸 늘이기 그림으로. 크림 판 + 같은 굵기(4px) 갈색 테두리 + 바깥 얇은 밝은 테두리, 버튼은 위아래 밝기 차이만.
  - A "깔끔한 종이" (`assets/sprites/ui/clean_a/`): 판·쪽지·코르크에 옅은 결. 결이 늘어나 번지지 않게 게임이 바둑판처럼 이어 붙이고, 그림은 가운데 칸 크기로 결이 되풀이되게 그림(이음매 없음).
  - B "거의 평면" (`clean_b/`): 결 없음.
  - 결과 카드도 A·B에서는 흔들리는 손그림 선·빗금 대신 둥근 크림 판 + 갈색 테두리.
  - 비교 그림 `2c-juice/compare/<화면>_<pc|phone>.png` (지금 | A | B).
- **임시 코드 (사용자가 A·B를 고르면 지움)**: `UiKit.look`과 `UiKit.PAPER`의 "old"·안 고른 묶음, `DevPanel._add_look_toggle`(로컬 웹 빌드 위쪽 "UI A/B" 단추, 기본 A, 누르면 장면을 다시 불러 바뀜), `assets/sprites/ui/`의 예전 그림·안 고른 폴더.
- **눈 검수 도구 (창 없음)**: `review/v0.7.0/2c-juice/export_qa.sh`(tools/를 넣은 검수용 웹 빌드 build/qa) + `qa_web.mjs`(헤드리스 Chromium) + `tools/qa_web.gd`(빌드 안에서 상태를 만들고 글자 칸 위치를 알려 줌). 보통 웹 빌드에는 tools/가 없어 안 붙음. 칸 찾기 함수는 `tests/test_ui_quality.gd`와 같이 씀.

## 19. 유료 게임 품질로 다듬기 (2026-11-13, 맥, 2c-polish)

### 19-1. 만든 것
- **UI 스타일 표** (ART_BIBLE 13): 색 18개, 둥글기 4가지(칩 12·버튼 22·판 28·알약), 테두리 4px 갈색 하나, 그림자 아래 6px 갈색 30%, 윗면 빛, 눌림 4px·8% 어둡게, 고름 3px 떠오름, 여백 8의 배수, 글자 제목 48·본문 34·보조 30·숫자 40·큰 숫자 72, 아이콘 받침 72·152. `UiKit` 상수 = 표 (`tests/test_ui_style.gd`가 표와 코드를 대조하고, 메뉴 코드에 표 밖 색·둥글기·글자 크기·간격 숫자가 있으면 실패).

- **다른 화면**: 시작 = 리본 제목, 이름표 달린 정보 띠(숫자 굴러감), "부스터 켜고 시작" + 켠 칸 체크·0개 "사기", [상점] 새 강화 점. 미션 = 알약 등급 줄, 머리글 알약, 쪽지(받침 아이콘, 두 줄 맞춤 문구, 막대, "경험치 +N 받음", 보조 [바꾸기] + 생선 가격, 받을 쪽지 1도 흔들림·받기 빛, 받은 쪽지 70%). 결과 = "이번 판 점수" 리본, 큰 점수, 기록 표, 최고·가진 생선 한 줄, "다음 판 부스터", 따뜻한 갈색 가림. 들어올 때 요소마다 0.04초씩 늦게.
