# 아기 고양이 무리 + 액션 시험판 (2026-11-17, cat-parade 브랜치, 버전 그대로)

시험판의 목적은 하나다. 사용자가 "때리고 부수는 게임이 되니 더 재미있는가"를 판단한다. 그림은 최소로 쓰고, 다듬기는 하지 않았다. 설계·수치는 GAME_SPEC "아기 고양이 무리 + 액션 시험판" 절에 있다.

## 영상 (실제 속도 `*_real.mp4`, 4배 느리게 `*_slow.mp4`, PC 1280x720 화면 전체)
| 파일 | 장면 |
|---|---|
| `float_flat` | 떠다니는 6마리, 평지 (구름 방석, 둥실 박자가 아기마다 다름) |
| `float_jump`·`float_double` | 점프·더블점프: 스프링으로 늦게 따라와 출렁임, 무리 전체가 HUD 밑으로 같이 눌림 |
| `float_flock` | 비둘기 밑 지나가기 ("그대로!") |
| `stomp` | 화분 → 물탱크 → 비둘기 연속 밟기 ("밟기!", "밟기 x2", "밟기 x3", 점수, 통 소리가 올라감) |
| `punch`·`fetch`·`sparkle` | 턱시도 냥펀치(실외기로 날아가 부숨) · 치즈 물어 오기(높은 생선을 놓치자 물어 옴, 콤보 이어짐) · 삼색 반짝 코(앞 생선 3마리가 황금) |
| `hit` | 피격: 하트 -1, 가장 나중에 온 아기가 "냐!" 하며 빙글 날아가 사라지고 남은 아기 움찔 |
| `meet` | 만남: 기다리던 아기가 야옹 + 하트, 구름이 퐁 생기며 자기 자리로 날아옴 |
| `slide_sign` | 슬라이딩으로 낮은 간판 밑 지나가기 ("숙여!", "!" 밑 아래 화살표) |
| `dive_stomp` | 공중 내려찍기로 실외기 밟기 |
| `dive_slide` | 점프 → 내려찍기 → 누른 채 닿아 슬라이딩으로 이어져 간판 밑 지나가기 |

정지 화면: `float6_pc.png`·`float6_phone.png`(6마리), `hud_ready_*`(능력 준비 고리), `sign_teach_*`(슬라이딩 첫 안내), `result6_*`(결과 카드).

다시 만들기: `GODOT=<경로> bash review/v0.7.0/2c-juice/export_qa.sh` → `PLAYWRIGHT=<경로> node review/cat-parade/qa_web.mjs build/qa <폴더> parade_action x pc` (장면만: `parade_action-stomp-slide_sign`, 정지: `parade_still x pc|phone`) → `python3 review/cat-parade/action/make_videos.py <폴더>`. 밟기 장면은 `tools/qa_stomp_plan.gd`가 같은 속도(600)·같은 상대 자리에서 밟히는 입력을 찾아 그대로 재생한다.

## 그림
- 간판 1장(`assets/raw/action/sign.png`), 주인공 슬라이딩 4칸 1장(`slide.png`). 둘 다 Codex에서 한 번에 나와 다시 뽑기 0번 (요청문 `prompts/`). 사용자가 Codex로 1장을 정해 줘서 오픈 에셋은 따로 찾지 않았다.
- 떠다니는 아기는 기다리기(앉음) 그림을, 날아가는 아기는 예전 놀란 펄쩍 그림 1장을 다시 썼다. 구름 방석은 게임 배경 구름(`backdrop/cloud1.png`)이다.

## 밸런스 (봇)
실행: `godot --headless --path . -s res://review/cat-parade/action/action_report.gd -- --seeds=20`. 아기 무리·능력·슬라이딩(간판 앞 0.3초 + 실수)은 두 봇 다 켬. 차이는 화분·실외기를 넘느냐(피하기), 최대로 뛰어 내려오며 밟느냐(밟기)뿐이다. 600초에서 끊음.

시드 1~20, 한 판 최대 600초, 봇 = tests/balance_bot.gd
| 실력 | 봇 | 판 길이 평균(초) | 가운데값(초) | 점수 평균 | 밟기 점수 평균 | 판당 밟은 수 | 판당 하트 잃음 | 하트 0으로 끝 |
|---|---|---|---|---|---|---|---|---|
| 초보 | 피하기 | 93 | 99 | 23174 | 68 | 0.9 | 0.9 | 2/20 |
| 초보 | 밟기 | 91 (-2%) | 84 | 17926 (-23%) | 348 | 7.2 | 0.9 | 2/20 |
| 익숙함 | 피하기 | 217 | 176 | 101515 | 42 | 0.3 | 1.4 | 3/20 |
| 익숙함 | 밟기 | 203 (-6%) | 176 | 75150 (-26%) | 796 | 14.8 | 1.4 | 2/20 |
| 숙련 | 피하기 | 563 | 600 | 350849 | 0 | 0.0 | 2.4 | 6/20 |
| 숙련 | 밟기 | 461 (-18%) | 469 | 215338 (-39%) | 2067 | 32.8 | 3.2 | 13/20 |

- 밟기가 판을 지나치게 쉽게 만들지는 않는다. 판 길이는 초보 -2%, 익숙함 -6%, 숙련 -18%로 같거나 짧아진다. 빠른 속도에서는 밟으러 높이 뛰다 옆에 맞는 일이 늘어서다(숙련 하트 잃음 2.4 → 3.2).
- 점수는 오히려 23~39% 낮다. 밟기 점수(판당 350~2,070점)보다 놓친 생선 점수가 크다. 생선 길이 "넘기" 동작에 맞춘 호라서, 밟으러 뛰면 생선 줄에서 벗어나기 때문이다. 밟기를 노릴 까닭을 만들려면 사용자가 정할 것이 있다: 밟기 점수를 올리거나, 밟기 궤적에 생선을 깔거나.
- 피하기 봇도 우연히 판당 0~1번 밟는다(내려오다 윗면에 닿으면 피격 대신 밟기).

## 처음 보는 눈 (1차례, "게임 디자이너", 영상만)
| 물음 | 답 |
|---|---|
| 밟기가 읽히는가 | dive_stomp는 읽힘. stomp 물탱크는 반쯤: 별·글자가 탱크 다리 가운데에 떠서 맞닿는 순간이 덜 보임 (중) |
| 능력이 뭘 했는지 보이는가 | 냥펀치·반짝 코는 잘 보임. 물어 오기는 노리는 생선이 작아 과정이 덜 보이고, 결과("물어 왔다!", 생선 +1)는 보임 (중) |
| 아기가 화면을 가리는가 | 상: 피격 때 날아가는 아기와 "냐!"가 왼쪽 위 생선 수를 덮음 → **고침**(뒤로 빨리 빠지며 살짝만 뜸, "냐!"는 처음 자리 옆에 짧게). 중: 피라미드 맨 아래 아기가 주인공 꼬리 근처, 날아간 장애물 조각이 아기와 겹침. 하: 점프 때 주인공·앞길·장애물을 가리지 않음 |

"상"만 고쳤다. 중·하는 시험판이라 다듬지 않았다(사용자가 액션 방향을 고르면 그때).
