**"통과"의 뜻:** 경로가 하나 있다는 뜻이 아니다. 위험마다 **누름 창 100ms 이상(가운데서 ±50ms 흔들려도 통과)**, 누름 길이가 흔들려도(톡 50~100ms 등), 착지 깊이가 달라도(0.3·0.6·0.87초), 판정을 8픽셀 넓혀도 통과. 이 기준으로 바꾸자 처음 설계에서 실패 29건이 나왔고, 고친 뒤 0건이다.

## 1. 장애물 4종

이미 있는 입력에 하나씩 대응한다. 새 조작은 없다.

| 장애물 | 정답 | 그림 크기 | 판정 상자(폭 x 높이) | 처음 나옴 |
|---|---|---|---|---|
| **화분 무리** | 살짝 눌러 뛰기 (빨라지면 톡) | 84x48 | 48 x 0~38 | 단계 1 |
| **낡은 실외기** | 길게 (빨라지면 중간) | 140x117 | 110 x 0~88 | 단계 1 |
| **물탱크 탑** | 더블점프 (한 번 점프론 못 넘음) | 148x320 | 84 x 0~285 | 단계 3 |
| **비둘기 떼** | 그대로 달리기·낮게 뛰기. 크게 뛰면 맞음. 더블로 위로 넘어도 됨 | 218x72 | 150 x **240~310**, 초당 120으로 다가옴 | 단계 1 |

- 고양이 판정: 장애물에 대해서만 몸 타원의 80%(120x74). 그림이 살짝 스쳐도 맞지 않는 쪽으로 기운다.
- 비둘기 높이: 사용자 예시는 "머리 높이"였지만 **달리는 머리 높이(92)에 두면 낮은 점프로 피할 수 없다**. 재 보니 톡 100ms의 머리 위끝이 220~230이라, 240부터 둬야 낮은 길이 살아 있다. 그래서 "점프한 머리 높이"다. 뛰지 않으면 안전하고, 크게 뛰면 부딪힌다.
- 비둘기 위치는 시간이 아니라 **고양이 x의 함수**로 정한다. 만들 때부터 날면 5초에 약 600픽셀 어긋나 N4·H2 겹침이 깨진다.

### 피할 수 있는 시간 (계산 결과, 전체는 design_check_result.md)

| 장애물 | 속도 | 톡 창 | 정답 창 | 보인 뒤 마지막 누름까지 (PC) |
|---|---|---|---|---|
| 화분 | 430 / 610 / 950 | 70 / 190 / 285ms | 215 / 340 / 435ms (중간) | 2.02 / 1.42 / 0.89초 |
| 실외기 | 430 / 610 / 950 | 0 / 0 / 35ms | 195 / 355 / 495ms (길게) | 1.94 / 1.34 / 0.82초 |
| 물탱크 | 550 / 610 / 950 | 0 | 205 / 245 / 355ms (꼭대기 ±50ms 더블) | 1.05 / 0.90 / **0.37초** |
| 비둘기 | 430 / 950 | 뛰지 않으면 안 맞음 | 길게 뛰어도 맞는 때는 약 0.85초 동안뿐 | 1.71 / 0.88초 |

읽는 법:
- 물탱크 창이 430에서 95ms로 좁아서 550부터 나온다.
- 같은 장애물은 빨라질수록 창이 **넓어진다**. 어려워지는 건 판단 시간이다. 그래서 난이도는 5번의 밀도·섞임으로 올린다.
- **가장 빡빡한 곳: 물탱크 950, 판단 0.37초.** 입구 여유 2.1초로 보강했지만 2a 플레이 확인 대상이다.

### 소품과 헷갈리지 않게

지금 소품(굴뚝·물탱크·안테나·화분·난간·실외기)은 판정이 없는데 모양이 장애물과 겹쳐서 **가장 큰 위험**이다. 규칙 넷을 함께 쓴다.

1. **다홍색 리본**: 장애물은 전부 다홍 띠가 있다. "리본 = 부딪힘" 하나만 배우면 된다. 소품에는 다홍을 쓰지 않는다.
2. **접지 그림자**: 장애물에만 있다.
3. **윤곽**: 장애물은 선이 소품의 1.3배 진하고 밝은 테두리가 있다(고양이와 같은 규칙).
4. **소품을 물러나게**: 크기 0.8배, 채도 55%, 불투명도 60%. 그리고 **겹치는 소품 3종(화분·실외기·물탱크)은 옥상 위에서 뺀다**. 남는 건 굴뚝·안테나·난간. 2a부터 적용한다(안 그러면 2a 플레이 판단이 오염됨).

`mockup_obstacles.png`의 굴뚝·안테나가 소품 규칙을 적용한 모습이다. 정지 화면으로는 구분되지만 빠를 때도 되는지는 플레이로 확인해야 한다.

## 2. 하트 3개

- 장애물에 부딪힘: 하트 -1, **1.5초 무적**(깜빡임). 고양이는 그림만 비틀거리고 속도는 그대로다(속도를 바꾸면 건너기 계산이 흔들림). 맞은 장애물은 살짝 튕겨 나가 사라진다.
- 하트 0: 게임 끝. 떨어지면 하트와 상관없이 끝(사용자 결정). 종이상자 구제는 그대로.
- **벽 투명화는 하트를 잃지 않는다**(제안). 옥상 높이 차는 지금도 자주 생겨서, 깎으면 하트가 장애물이 아니라 벽에 다 쓰인다. 투명화 중에는 장애물도 맞지 않는다.
- 하트는 저장하지 않는다(판마다 3개). 저장 형식이 안 바뀌어 메이저 버전 올림이 필요 없다.

- 위치: **화면 위 가운데**. 눈은 고양이와 오른쪽 장애물 사이에 머물러서 왼쪽 위 숫자 줄보다 잘 보이고, `expand` 화면에서도 가운데다.

| 음악 | 짧은 상승 음(직접 합성)과 함께 곡 `pitch_scale`을 단계마다 +1.3% (최대 약 1.12). 웹 동작은 2a에서 확인 |
| 고양이 | 달리기는 이미 속도에 맞춰 빨라짐. 오를 때 스프링 충격 1회 |

### 빨라져도 항상 건널 수 있는지 확인하는 법

1. **기존 테스트 재사용**: `test_roofs`·`test_structures`가 속도별로 틈·판·트램펄린을 검사한다. 검사 속도를 단계 표의 값으로 바꾼다.
2. **`arrival_speed` 고치기**: 지금 "초당 1.5"로 도착 속도를 계산해서 단계 곡선과 안 맞다. **"다음 단계 속도"로 계산**한다(`next_roof`는 speed만 받음). 앞 2200픽셀은 많아야 5.1초라 가장 짧은 단계 15초보다 짧아서, 한 단계만 넘는다.
3. **구간 사람 통과 검사**(근사로 이미 실행, 결과는 design_check_result.md): 10개 구간 x 나오는 전 단계 x 착지 깊이 3종. 실패 0. 황금 생선 먹는 길도 전 단계 있음.
4. **만든 뒤 단계가 오른 경우**(근사로 이미 실행): 만든 속도보다 다음 단계 속도로 달려도 전 조합 통과.
5. **검사기 자체 검사**: 못 건너는 틈(2.4배)과 한 번 점프로 물탱크 넘기를 불가능하다고 답하는지, 물탱크 정답이 더블인지 확인.
6. 2a에서 3~5를 진짜 `RunnerSim`으로 다시 만들어 자동 테스트로 둔다(트램펄린·전봇대 포함).

## 5. 손으로 짠 구간

그림: `segments.png`. 데이터는 지금은 `segments.json`이고, 게임에서는 GDScript 상수로 둔다(웹 내보내기 포함 여부를 신경 쓰지 않게).

**핵심 결정: 길이를 픽셀이 아니라 "초"로 적는다.** 옥상 길이·장애물 자리 = 초 x 속도, 틈 = 최대 점프 거리의 비율. 같은 구간이 어느 속도에서나 같은 박자로 읽히고 속도마다 따로 만들 필요가 없다.

**알려진 문제와 대응:** 초로 적으면 빨라져도 박자가 같아 저절로 어려워지지 않는다. 대응 셋을 쓴다.
1. **구간 밀도**: 옥상의 첫 장애물 **뒤** 간격에 밀도를 곱한다. 입구 여유는 안 줄인다(줄이면 물탱크 앞 시간이 모자라 29건 실패의 주원인이 됨).
2. **섞임**: 어려운 구간 비중을 올린다(아래 표).
3. **쉼 줄이기**: 쉼 옥상 수를 줄인다(아래 표).

정직한 측정: 입구 여유를 지키면 밀도 효과는 구간 평균 4.33초 → 3.87초로 **약 11%뿐이다**. 어려움 구간도 입력 자체는 대부분 중간·톡(더블 1번 + α)이다. **뒤 단계의 긴장은 미리 보는 시간 감소와 쉼 감소에 주로 달렸고, 충분한지는 플레이로만 안다.** 부족하면 2a에서 장애물이 더 많은 구간을 추가한다.

| 구간 | 난이도 | 내용 | 입력 (처음 속도 → 950) | 나오는 속도 |
|---|---|---|---|---|
| E1 첫 화분 | 쉬움 | 화분 하나, 위에 생선 | 중간 → 톡 | 430~ |
| E2 작은 틈 | 쉬움 | 좁은 틈, 아이템 자리 | 톡 | 430~ |
| E3 실외기 | 쉬움 | 실외기 넘고 생선 줄 | 길게 → 중간 | 430~ |
| E4 비둘기 지나가기 | 쉬움 | 뛰지 않으면 바닥 생선 8개 | 그대로 달리기 | 430~ |
| N1 화분·실외기 박자 | 보통 | 낮게, 그다음 길게 | 톡, 길게 → 톡, 중간 | 490~ |
| N2 틈 뒤 화분 | 보통 | 오르막 틈, 착지 뒤 화분 | 톡, 톡 → 중간, 톡 | 490~ |
| N3 물탱크 | 보통 | 첫 더블 장애물, 위에 황금 | 더블 | 550~ |
| N4 낮게! | 보통 | 화분 + 비둘기: 낮게 밑으로, 또는 더블로 위로 | 톡 | 610~ |
| H1 황금 물탱크 | 어려움 | 더블로 황금, 내려와 곧 틈 | 더블, 톡 → 더블, 중간 | 670~ |
| H2 계단과 비둘기 | 어려움 | 실외기, 오르막 틈, 비둘기 + 화분 | 중간, 중간, 톡 | 670~ |

### 이어 붙이는 규칙

순서: **구간 → 쉼 자리 → 구간 → ...** `next_roof`는 바꾸지 않고 **위에 구간 배치 클래스를 얹는다**(`test_roofs`의 너비 검사를 지키려고). 쉼 옥상은 지금 `_plain_roof`(생선 포함)다. 쉼 자리에서 지금 생성기의 트램펄린·전봇대 넓은 틈이 나온다.

**첫 판 고정 대본: E1 → E2 → E3 → E4 → E2(첫 질주).** 약 20~25초 안에 피할 것·노릴 것·질주가 다 나온다(3-1 체크). 대본이 끝난 뒤부터 아래 표로 섞는다.

| 단계 | 쉬움 | 보통 | 어려움 | 쉼 옥상 수 | 쉼 자리의 특수 틈 확률 |
|---|---|---|---|---|---|
| 1~2 (대본 뒤) | 80% | 20% | | 1~2 | 0.3 |
| 3 | 60% | 40% | | 1~2 | 0.4 |
| 4 | 40% | 60% | | 1~2 | 0.5 |
| 5 | 30% | 50% | 20% | 1~2 | 0.5 |
| 6 | 20% | 50% | 30% | 1 | 0.5 |
| 7~9 | 10% | 45% | 45% | 1 | 0.5 |
| 10~ | | 40% | 60% | 0~1 (어려움 뒤엔 1) | 0.5 |

- 특수 틈 확률을 v0.5.0의 0.3보다 올린 이유: 쉼 옥상에서만 나오니 트램펄린·전봇대가 크게 줄어든다(architect 어림 약 1/5). 봇으로 확인한다.
- 같은 구간 연속 금지.
- 구간 입구는 앞 옥상 높이에 맞춰 전체를 올리거나 내려 옥상 높이 범위(120~330) 안에 넣는다. 물탱크가 있는 구간은 높이 240 이하(세로 카메라).
- 시드: 구간 고르기는 `RandomNumberGenerator` 하나, 같은 시드 = 같은 맵.

## 8. 밸런스 봇 계획

`tests/balance_bot.gd`에 넣는다. 지금 `_plan`은 옥상 단위 계획이라 재작성에 가깝다. 봇은 앞 위험을 보고 정답 동작을 고르되 실력별 타이밍 오차를 둔다. 시드 30개, 실력별 최대 900초. 비교 기준 v0.5.0: 초보 61 / 익숙함 503 / 숙련 900초.

| 잴 것 | 목표 |
|---|---|
| **한 판 길이** 가운데값 | 초보 **60~90초**, 익숙함 **180~300초**, 숙련 **600초 이상** |
| 첫 30초 안에 끝나는 판 (초보) | 10% 이하 |
| **끝난 이유** | 떨어짐 50~70%, 하트 0이 30~50% (한쪽만이면 하트나 틈이 장식이 됨) |
| **하트 잃는 곳** | 어느 한 장애물이 50%를 넘지 않음 |
| 단계별 구간 통과율 (초보) | 단계가 오를수록 **내려가야 함** (밀도가 효과 있는지 보는 지표) |

## 9. 구현 나누기

한 번에 만들지 않고 플레이로 끊는다.

| 단계 | 내용 | 확인 |
|---|---|---|
| **2a-1** | 속도 표(`speed_curve.gd`, `balance.gd`), `arrival_speed`, 깨지는 테스트(`test_runner`, `test_balance`), 최소 속도선·글자 | 속도만 먼저 플레이: "1분 안에 느끼는가" |
| **2a-2** | 소품 3종 끄기, 장애물, 하트(`invuln_time`), 구간 배치 클래스, `RunnerSim` 구간 검사, 봇 교체. 시트 그림은 임시로 그대로 올림 | 피하는 맛, 억울함, 탭 실측 |
| **2a-3** | 질주(전용 분기, 착지 옥상), 털실, 황금, 쿠키, (고르면) 통조림 | 아이템 먹을 때 판이 바뀌는가 |
| **2b** | HUD 완성, 소품 규칙, 7번 손맛, 소리, GIF | QUALITY_BAR 3·3-1 |

구현 함정 (architect가 코드에서 확인):
- **무적은 `ghost_time`을 재사용하지 않는다.** 그 값은 벽 통과·떠오르기·더블점프 금지도 켠다. `invuln_time`을 따로 두고 깜빡임 그림만 둘을 함께 본다.
- **충돌 판정은 `step()` 끝에 넣지 않는다.** 땅 위·탑승·떠오름 상태는 일찍 return하므로, `_pick_items` 옆에 둔다(구제 중 제외).
- **`_pick_items`는 생선이 아니면 전부 상자로 처리**한다. `match`로 나눈다.
- 트램펄린·전봇대의 `no_ghost` 벽 처리와 질주는 겹치지 않게 전용 분기.

버전: 최고 기록 저장 형식은 그대로라 v0.6.0(마이너).

## 11. 사용자가 정할 것

1. 추가 아이템: 통조림 / 캣닢 / 방울 / 없음 (추천: 통조림)
2. 하트 회복: A 쿠키 / B 생선 / C 퍼펙트 (추천: A만)
3. 벽 투명화는 하트를 안 잃음 (추천: 안 잃음)
4. 질주 아이템 화면 이름. "츄르"는 다른 회사의 실제 제품 이름이라 상표 문제가 있을 수 있어 그림과 요청문에서는 "짜먹는 간식"으로 뺐다. 게임에 "츄르" 글자를 쓰지 않는 쪽을 추천(예: "냠냠 질주"). 게임 안 글자가 없으면 아이콘만으로도 됨
5. 비둘기 높이: "머리 높이" 대신 "점프한 머리 높이"(뛰지 않으면 안전)로 바꿈 (추천: 그대로)
6. 장애물 그림: 시안의 귀여운 톤 + 다홍 리본으로 충분히 "위험"으로 보이는지 (시안 보고 판단)
7. 속도 표 (시안 수치 그대로면 그대로)

## 12. 디렉터 판정과 사용자 결정 (2026-11-08)

디렉터 판정: 설계 승인. 사람 기준 검사(누름 창 100ms·착지 깊이 3종)로 실패 29건을 찾아 고친 점, 질주 끝에 착지 옥상을 만드는 방식, 단계별 구현 나누기(2a-1 → 2a-2 → 2a-3 → 2b)가 좋다. 시안 그림체는 기존과 잘 맞고 질주 장면(빛남·잔상·속도선·팡!)이 의도대로다. 걱정: 다홍 리본이 "위험"보다 "선물"로 읽힘(리본 단 비둘기는 친구처럼 보임).

사용자 결정:
1. **위험 표시 = 느낌표.** 장애물에서 다홍 리본을 뺀다. 장애물이 화면에 들어올 때 위에 빨간 "!"가 통 떴다 사라지고, 장애물 자체는 진한 윤곽선(소품의 1.3배)·밝은 테두리·접지 그림자로 소품과 구분한다. 비둘기는 화난 눈썹(귀여움은 유지). 장애물 그림은 리본 없이 다시 뽑는다(2a-2). 소품 물러나게 하기(0.8배·채도 55%·불투명도 60%, 겹치는 3종 제거)는 그대로.
2. **하트 회복 = 하트 쿠키만**(PLAN 2번 A). 봇이 초보 목표에 못 미치면 그때 생선 회복을 다시 묻는다.
3. **추가 아이템 = 생선 통조림 + 금빛 방울.** 통조림: 화면 안 장애물 전부 "펑" → 생선. 금빛 방울: 다음 한 번의 부딪힘을 막음(하트 HUD 옆에 방울 표시, 막을 때 "딸랑" + 방울 깨짐). 둘 다 2a-3에서 핵심 아이템 뒤에 넣는다. 아이템 자리 우선순위에 넣는 방식은 2a-3 설계에서 정함.
4. **질주 아이템 이름 = 글자 없이 아이콘만.** 게임 안에 "츄르" 등 제품 이름을 쓰지 않는다. 먹는 순간 글자 대신 아이콘 + 효과만.
5. 디렉터가 그대로 받은 것: 벽 투명화는 하트를 잃지 않음, 비둘기 높이는 "점프한 머리 높이"(240~310), 속도 단계표 그대로.

다음: 2a-1(속도 표 + 최소 속도선·글자) → 사용자 플레이로 "1분 안에 빨라짐을 느끼는가" 확인.
